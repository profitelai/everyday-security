# DNS-002 · Registrar transfer lock is enabled

## Why it matters
A domain transfer to another registrar needs only the authorisation code and a request. The transfer lock is a status the registrar sets so that such requests are refused until you remove it, which blocks the simplest way to steal a domain: an attacker who has obtained the authorisation code and files a transfer request at another registrar is refused while the lock holds. It does not help if the attacker can log in and unlock it, which is why DNS-001 matters too.

## How to test
```bash
whois example.com | grep -i 'status'
```
Look for `clientTransferProhibited` in the domain status lines. Many country-code registries show different or fewer statuses; for those, check the lock switch in the registrar's control panel instead. The status names are defined in RFC 5731.

## Pass criteria
The domain shows `clientTransferProhibited` (or the registrar panel shows the transfer lock on). For domains the business cannot lose, a registry-level lock (statuses beginning `server`, such as `serverTransferProhibited`) is available from some registrars and is a stronger result.

## Fix
Turn on "transfer lock" or "registrar lock" in the registrar panel. Optionally also request `clientUpdateProhibited` and `clientDeleteProhibited` where offered. Keep the transfer authorisation code out of email and chat, and regenerate it after any exposure. For critical domains ask the registrar about registry lock, which usually requires an out-of-band confirmation to change.

## Risk and rollback
A lock must be lifted before a legitimate transfer, and an update lock must be lifted before nameserver or contact changes, so plan for a short unlock window. Rollback is the reverse: unlock for the duration of the legitimate operation and lock again as soon as it completes.
