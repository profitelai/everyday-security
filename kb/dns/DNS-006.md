# DNS-006 · Zone transfers (AXFR) are refused to the public

## Why it matters
AXFR exists so a secondary server can copy a whole zone. If the primary hands it to anyone who asks, an outsider gets the complete list of names in one request, including staging, admin and internal-looking hosts that were never meant to be advertised. RFC 5936 says an implementation should offer a way to restrict transfers.

## How to test
```bash
for ns in $(dig +short NS example.com); do
  echo "== $ns"
  dig +noall +answer +time=5 +tries=1 AXFR example.com @"$ns"
done
```

## Pass criteria
Every nameserver refuses the request (no records are returned; typically `Transfer failed` or a REFUSED status). Transfers may be permitted only to named secondaries, ideally authenticated with TSIG, which an outside test cannot see.

## Fix
BIND: restrict with `allow-transfer { 192.0.2.53; };` (your secondary's address) or a TSIG key, and use `allow-transfer { none; };` when there are no secondaries. PowerDNS Authoritative: set `allow-axfr-ips` to the secondaries only. Managed DNS providers normally refuse AXFR unless you switch it on; confirm that setting. Reload and re-run the test.

## Risk and rollback
A list that is too narrow stops real secondaries from syncing, and their data then goes stale. After the change confirm that each secondary shows the primary's current SOA serial. Rollback: restore the previous list and reload.
