# DNS-008 · No A or AAAA record points at an IP address you have released

## Why it matters
Cloud and hosting providers recycle public IP addresses. If a server is shut down and its address released while the DNS record stays, the next customer who receives that address can answer for your hostname. That is the address-based cousin of a dangling CNAME, and it is harder to spot because the name still resolves.

## How to test
1. Export the zone and list every A and AAAA record:
```bash
while read -r h; do
  for ip in $(dig +short A "$h"; dig +short AAAA "$h"); do echo "$h $ip"; done
done < names.txt
```
2. Compare each address with the inventory of addresses you currently hold (cloud console, hosting panel, server list). `whois ADDRESS` shows who the address belongs to, which helps when the inventory is incomplete.
3. For any address not in the inventory, find out who owns the record and whether the service is still running.

## Pass criteria
Every A and AAAA record points to an address that is in your current inventory, or to a third-party service you knowingly rely on. Nothing points to space you released or never owned.

## Fix
Delete the record or point it at the live service. When retiring a server, remove the DNS record first, wait for the record's TTL to elapse, then release the address. Where the provider allows it, reserve a static address so it is not lost by accident when a machine is rebuilt.

## Risk and rollback
Removing a record that a forgotten client still uses causes an outage for that hostname. Check traffic to the old address before deleting, and keep a zone export. Rollback: re-add the record from the export.
