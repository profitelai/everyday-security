# DNS-004 · At least two nameservers on independent infrastructure answer for the domain

## Why it matters
If the only server that can answer for your zone goes down, every name under the domain stops resolving. RFC 2182 advises placing secondary servers in different networks and places so one outage cannot silence the zone. Two servers in the same rack, or under one account with one provider, share the same failure.

## How to test
```bash
dig +short NS example.com
for ns in $(dig +short NS example.com); do
  echo "== $ns"; dig +short A "$ns"
  dig +norecurse +short SOA example.com @"$ns"
done
```
Every listed server should answer with the same SOA serial. Then run `whois` on each server address and compare the network owners to see whether they are really different.

## Pass criteria
At least two nameservers are delegated, each answers authoritatively with the same serial, and they sit on different networks. A single managed DNS provider with its own geographically spread network is a reasonable result if the dependency is documented; two servers of one small host are a finding.

## Fix
Delegate to at least two servers on separate networks. For important domains add a second DNS provider and keep both in sync through zone transfer from a hidden primary or the providers' APIs. Update the nameserver list at the registrar so it matches the zone.

## Risk and rollback
Two providers can disagree if a record is changed in only one, which gives intermittent wrong answers; automate the sync and compare both after every change. DNSSEC with two providers needs extra care. Rollback: remove the added server from the registrar delegation first, then from the zone.
