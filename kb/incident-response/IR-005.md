# IR-005 · Containment steps are rehearsed per system, and evidence is preserved before anything is wiped or rebuilt

## Why it matters
Containment stops damage from spreading; evidence preservation lets you learn how the attacker got in, decide whether personal information was exposed, and support an insurance claim, a police report or a regulator. The two pull in opposite directions: the fastest containment (rebuild the server) destroys the best evidence. Public guidance says to isolate affected systems, reset compromised credentials, and take care not to destroy evidence of the breach. Each kind of system in a small business has its own safe way to do this, and it is better to decide it in advance.

## How to test
For each asset class below, ask the technical responder to show, without performing it, the exact commands or console steps and where the result is saved. Where it is safe, do a dry run on a test instance.
- Linux server or VPS: how to cut network access but keep the machine running (provider firewall or security group rule, not just stopping services), how to take a disk snapshot from the provider console, how to capture volatile data first if the owner wants it (`ss -tunap`, `ps auxww`, `last -a`, `w`, `lsof -nP +L1`), and where copies go (a different account or machine). Check that copies get a checksum (`sha256sum`) and a written note of who took them and when.
- Website or CMS: how to put up a maintenance page, how to preserve the web root, database and web server logs before cleaning, and how to rotate admin, database and API credentials after.
- Mail: how to stop outbound sending (queue hold with `postsuper -h ALL` on Postfix, or the provider's suspend control), how to export message headers of suspicious messages, and how to disable forwarding rules and sessions in compromised mailboxes.
- Cloud and SaaS accounts: how to revoke sessions and tokens, reset credentials and MFA, list recent sign-ins, API keys, forwarding rules and new admins, and export the audit log before the retention window closes.
- Laptops and phones: how to isolate from the network, whether to power off or keep running, and who may image a device.
Also confirm the plan says who may order a wipe, and that nobody wipes before the lead agrees.

## Pass criteria
Each class has a written containment procedure that isolates without destroying data, an evidence step (snapshot, log export, or image) that comes before cleaning, a chain-of-custody note (who, when, hash, storage location), and a credential-rotation list. Evidence copies are kept in a place the attacker's access does not reach. The plan forbids wiping, reinstalling or deleting logs before the lead releases the system.

## Fix
Write one half-page procedure per asset class. Pre-create the permissions needed to snapshot (for example a provider role that can create snapshots but not delete them). Keep a "rotation list" of every key, token and password stored on each system. For serious cases, plan to bring in a professional forensics firm and give them the unaltered snapshot rather than trying to analyse a live, changing machine yourself.

## Risk and rollback
Isolating a production system interrupts service, and some commands change the machine state while capturing it. Accept that trade-off deliberately and record it. Whether to power off or keep a compromised machine running depends on the case; the guidance leaves this to judgment, and a forensics adviser can help decide. Rollback: restore network access by reversing the firewall or security-group change recorded in the plan once the lead approves.
