# IR-006 · Logs needed to investigate an incident are kept off the host for long enough, with synchronized clocks

## Why it matters
Many intrusions are discovered weeks or months after they began. If the web, mail, authentication and cloud audit logs are only on the compromised machine, the attacker can delete them, and if rotation discards them after a few days there is nothing left to examine. Investigators need to answer: when did it start, what was accessed, was personal information taken. Log management guidance recommends a policy for what is generated, stored and for how long, and international logging guidance stresses centralised, protected logs and consistent time.

## How to test
Run on each server and adapt names to your stack.
```bash
journalctl --disk-usage; grep -E '^(Storage|SystemMaxUse|MaxRetentionSec)' /etc/systemd/journald.conf /etc/systemd/journald.conf.d/* 2>/dev/null
ls -l /var/log/auth.log* /var/log/nginx/*access* /var/log/apache2/*access* /var/log/mail.log* 2>/dev/null
grep -rE 'rotate|daily|weekly' /etc/logrotate.d/nginx /etc/logrotate.d/apache2 /etc/logrotate.d/rsyslog 2>/dev/null
timedatectl status | grep -E 'synchronized|NTP'
grep -rE '^\s*[^#].*@' /etc/rsyslog.conf /etc/rsyslog.d/ 2>/dev/null
sudo zgrep -h . /var/log/auth.log* 2>/dev/null | head -1
```
Then answer: What is the oldest authentication, web and mail entry you can read today? Are logs also copied to another machine or service that the server's admin account cannot erase (the `@@host` or `@host` lines in rsyslog, or a shipping agent)? For cloud and SaaS: is the audit log enabled, and what is its retention in the provider's plan (many default to 90 days or less)? Are timestamps in UTC or a documented zone on all systems?

## Pass criteria
Authentication, web access and error, mail and admin-action logs from each server are available for the retention period the business chose (as a working default, 90 days immediately searchable and 12 months archived; the right figure depends on how fast you would notice a breach and on sector rules), and a copy sits off the host in a place a compromised server cannot rewrite. Clocks are synchronized with NTP. Cloud and SaaS audit logging is enabled and exported before the provider's window expires. Personal data in logs is minimised and covered by the retention schedule (see PRIV-005).

## Fix
Raise retention in logrotate (`rotate 90` with `daily`) and journald (`MaxRetentionSec=`), enable persistent journal storage, install an NTP client such as chrony, and forward logs with rsyslog or a lightweight agent to a separate low-cost log host or object storage with write-only credentials. Switch on audit logging in the mail provider, cloud console, registrar and DNS host and set a reminder to export it. Turn on the web server's real client address logging when behind a proxy or CDN.

## Risk and rollback
Longer retention uses disk and may keep personal data (IP addresses, usernames) longer than your privacy policy says; reconcile both. Remote shipping adds a network dependency; make sure a log-host outage cannot block the application. Rollback: restore the previous rotation and journald settings from the backup copy of the config files, then reload with `systemctl reload` or `systemctl restart systemd-journald`.
