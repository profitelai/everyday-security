# CMS-003 · Few administrator accounts exist, none is named admin, and each has a strong password and a second factor

## Why it matters
An attacker who logs in as an administrator can install any plugin, which means running any code on your server. Guessing and stolen-password attacks go first to the username `admin` and to accounts left behind by former staff or agencies. WordPress core does not include two-factor login, so unless you added it, one reused password is the only barrier. Day-to-day writing does not need administrator rights, and every extra administrator is another password that can leak.

## How to test
```bash
wp user list --role=administrator --fields=ID,user_login,display_name,user_email,user_registered
wp user list --fields=ID,user_login,roles --format=csv
wp user get admin --field=ID        # an error means no such login exists, which is the pass result
wp user application-password list USER_ID --fields=uuid,name,last_used,last_ip
wp plugin list --fields=name,status | grep -iE 'two-factor|2fa|mfa|webauthn|passkey|security'
```
In the dashboard open Users, then each administrator's profile, to confirm the second factor is enrolled (this cannot be read from WP-CLI reliably, since each plugin stores it differently). Ask who each administrator is, whether they still work with you, and whether the email address is one you control.

## Pass criteria
- No account has the login `admin`, `administrator`, `webmaster`, the site's domain name, or an equivalent guessable login.
- Administrator accounts are limited to the people who need them (for most small businesses, one or two), each one a named person, with no shared login.
- Former staff, agencies and unknown accounts are removed or downgraded.
- Every administrator and editor uses a unique password from a password manager (long, not reused; see NIST SP 800-63B on length over complexity rules) and has a second factor, preferably an authenticator app, hardware key or passkey rather than SMS.
- Application passwords that are no longer used by a known integration are revoked.

## Fix
Create a new administrator with a personal login, log in as it, then remove or demote the old `admin` account while reassigning its content: `wp user delete OLD_ID --reassign=NEW_ID` (the handbook also describes renaming the login in the database, but a clean new account is safer). Demote day-to-day authors to Editor or Author. Install a maintained two-factor or passkey plugin and enrol every privileged user, keeping recovery codes offline. Where the business already has a single sign-on provider, use it. Review users and application passwords every quarter.

## Risk and rollback
Deleting a user without `--reassign` deletes their posts; always reassign. Enforcing a second factor can lock a person out if their phone is lost, so keep one spare administrator or recovery codes before enforcing it. Rollback for a lockout: use WP-CLI to create a temporary administrator (`wp user create`), fix the second-factor setting, then delete the temporary account.
