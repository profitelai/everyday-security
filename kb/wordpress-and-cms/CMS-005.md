# CMS-005 · The site does not reveal usernames or version numbers, and XML-RPC is off unless it is needed

## Why it matters
By default a WordPress site gives away the login names of its authors, through author archive redirects and the REST API users endpoint. A valid username halves the work of a password-guessing attack. The legacy `xmlrpc.php` interface lets a single request try many passwords and is used for pingback abuse; most small sites do not use it. Version strings in page source help attackers choose exploits, although hiding them is only a minor extra layer and never a substitute for updating (CMS-001).

## How to test
```bash
SITE=https://example.com
curl -s -o /dev/null -w "%{http_code} -> %{redirect_url}\n" "$SITE/?author=1"       # a redirect to /author/NAME/ reveals the slug
curl -s "$SITE/wp-json/wp/v2/users" | head -c 500                                  # a JSON list with "slug" values is a disclosure
curl -s -o /dev/null -w "%{http_code}\n" "$SITE/wp-json/wp/v2/users/1"
curl -s -X POST -H 'Content-Type: text/xml' \
  -d '<?xml version="1.0"?><methodCall><methodName>system.listMethods</methodName><params/></methodCall>' \
  "$SITE/xmlrpc.php" | head -c 300                                                 # a methodResponse list means XML-RPC is live
curl -s "$SITE/" | grep -io '<meta name="generator"[^>]*>'
curl -s "$SITE/" | grep -Eo '(wp-content|wp-includes)/[^"]+[?]ver=[0-9.]+' | head -5
curl -s -o /dev/null -w "readme.html %{http_code}\n" "$SITE/readme.html"
curl -s -o /dev/null -w "license.txt %{http_code}\n" "$SITE/license.txt"
```
Compare any slug that appears with the actual login names from `wp user list --fields=user_login,user_nicename`; if the public slug equals the login, the login is exposed.

## Pass criteria
- `?author=N` does not redirect to a slug that equals the login name, and the unauthenticated users endpoint is blocked (401 or 403) or returns only accounts you are happy to publish, with slugs that differ from login names.
- `xmlrpc.php` returns 403 or 404, unless a named tool needs it (a mobile app, a publishing client, or an integration plugin), in which case it is rate limited (CMS-004).
- No generator meta tag, and `readme.html` and `license.txt` are removed or not served. Version numbers in asset query strings are acceptable if CMS-001 passes.

## Fix
Use a display name that is not the login (Users, Profile, "Display name publicly as") and give authors a different nicename. Block the author-ID redirect and the anonymous users endpoint at the web server or with the `rest_authentication_errors` filter for logged-out visitors. Block XML-RPC at the server rather than relying on the `xmlrpc_enabled` filter, because that filter covers only methods that need authentication and not pingbacks. nginx: `location = /xmlrpc.php { deny all; }`. Apache: `<Files "xmlrpc.php"> Require all denied </Files>`. Remove the generator tag with the `the_generator` filter or a hardening plugin and delete `readme.html` and `license.txt` after each core update.

## Risk and rollback
Some tools use XML-RPC (for example the Jetpack connection and some desktop or phone publishing apps), and some plugins and themes call the REST users endpoint for logged-out features such as author lists; test those after the change. Deleted readme and licence files come back with each core update. Rollback: remove the `location` or `Files` block and reload the web server, and remove the added filter code.
