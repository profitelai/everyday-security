# CMS-002 · Unused plugins and themes are deleted, and every remaining one is maintained and from a trusted source

## Why it matters
Every plugin and theme is code that runs with the full rights of your site, and most WordPress break-ins come through that code rather than through WordPress itself. A deactivated plugin is still on disk, and many vulnerable plugin files can be requested directly even when the plugin is switched off. Abandoned plugins never receive fixes, so a flaw found after the last release stays open for good. Plugins and themes taken from pirated "nulled" bundles or unknown download sites regularly arrive with a backdoor built in.

## How to test
```bash
wp plugin list --fields=name,status,version,update,auto_update
wp plugin list --status=inactive --fields=name,version
wp plugin list --status=must-use,dropin --fields=name,status
wp plugin list --fields=name,version,wporg_status,wporg_last_updated   # data from WordPress.org; blank for premium or custom plugins
wp theme list --fields=name,status,version,update
```
For each remaining plugin and theme, open its page in the WordPress.org directory (or the vendor site) and record: date of last update, "tested up to" version, number of active installs, whether support threads get answered, and whether it has known vulnerabilities in the National Vulnerability Database or a public WordPress vulnerability database. Note where each one was downloaded from. Look inside `wp-content/mu-plugins` and for drop-in files such as `advanced-cache.php`; nobody should be surprised by what is there.

## Pass criteria
- No inactive plugins. Inactive themes: none, except one current default theme kept as a fallback (and the parent theme if a child theme is active).
- Every active plugin and theme is either in the official directory, or bought from the vendor's own site with a licence that provides updates.
- Each has been updated within roughly the last 12 months (rule of thumb, not a standard), or the owner has a written reason to keep it.
- No active plugin has an unpatched known vulnerability for the installed version.
- The list is short: each plugin has a reason written next to it.
- Must-use plugins and drop-ins are known and explained.

## Fix
Delete what is unused: `wp plugin delete NAME` and `wp theme delete NAME` (deactivate first if active). Replace abandoned plugins with maintained ones, or remove the feature. Prefer one well-supported plugin over three small ones that overlap. Download premium plugins only from the vendor. Add a quarterly reminder to repeat this review, and subscribe to security notices for the plugins you keep.

## Risk and rollback
Deleting a plugin can remove its settings or data (some delete their database tables on uninstall), and it can break pages that use its shortcodes or blocks. Back up first (CMS-009) and test on a staging copy for anything that touches page content. Rollback: restore the plugin files and database from the backup, or reinstall the plugin from the directory and re-enter settings.
