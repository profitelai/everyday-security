# CMS-011 · Comments and contact forms resist spam and cannot be abused to send email or upload files

## Why it matters
Comment boxes and contact forms are public doors that anyone, including bots, can knock on. Left open they fill the database with spam links that damage the site's reputation in search, and a poorly built form can be used to send spam in your name, which gets your mail server blocked and your business email delivered to junk. Forms that accept file attachments add a second risk: a dangerous file stored on your server.

## How to test
```bash
wp option get comment_moderation ; wp option get comment_previously_approved
wp option get default_comment_status ; wp option get default_ping_status
wp option get comment_registration ; wp option get comment_max_links
wp option get disallowed_keys | head -3
wp comment list --status=hold --format=count ; wp comment list --status=spam --format=count
wp comment list --status=approve --fields=comment_ID,comment_author,comment_author_url,comment_date --number=20
```
Then test the form itself, on your own site only. Submit it normally once to see the happy path. Send five rapid requests with a bot-like body and watch for throttling.
```bash
for i in 1 2 3 4 5; do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST https://example.com/contact/ \
    --data-urlencode "your-name=Test $i" --data-urlencode "your-email=test@example.com" \
    --data-urlencode "your-message=http://spam.example/$i http://spam2.example/$i"
done
```
(The field names depend on the form plugin; copy them from the page source.) Check whether the message was accepted, whether any hidden anti-bot field exists, whether the recipient address appears in the page source or can be changed by a form field, and what email address the notification came from (SPF, DKIM and DMARC alignment belongs to the mail pillar). If there is a file field, look at which file types and sizes it accepts.

## Pass criteria
- Comments are off where they are not wanted (`default_comment_status` is `closed`) or held for moderation (`comment_moderation` is 1, or previous approval is required); pingbacks and trackbacks are off (`default_ping_status` is `closed`).
- A spam filter or challenge (a maintained anti-spam service, a honeypot field, or CAPTCHA or Turnstile-style challenge) runs on comments and every public form, and the spam queue stays manageable.
- Repeated bot-like submissions from one address are throttled, rejected or flagged.
- The recipient of form email is fixed on the server; header-injection characters (new lines) in fields are rejected; mail is sent from your own domain through an authenticated mailbox or mail service rather than anonymous PHP mail.
- Upload fields, if any, restrict file types and size, store files outside the web root or where PHP cannot run (CMS-007), and the form data is not stored forever without a reason.

## Fix
In Settings, Discussion: close comments on new posts by default, require manual approval or previous approval, limit links per comment, and add known spam terms to the disallowed list. Install and configure one maintained anti-spam solution rather than several. Add a honeypot or a CAPTCHA-style challenge to forms, rate limit the form URL at the server (`limit_req` in nginx), and send form email through an authenticated SMTP account. Delete unused forms and old entries so the data is not a liability.

## Risk and rollback
A CAPTCHA or strict filter can block real customers, especially on mobile, and an over-eager spam filter can bin real enquiries; keep a place where blocked messages can be reviewed for a few weeks, and test the form after every plugin update. Closing comments on old posts removes discussion that visitors may value. Rollback: re-enable the setting in Settings, Discussion, or deactivate the anti-spam plugin and remove the added `limit_req` rule.
