# APP-001 · Private pages and records are checked against the logged-in user on the server

## Why it matters
Broken access control is the top category in the OWASP Top 10:2021. The classic form is an object reference such as `/invoice?id=1042`: if the server only checks that someone is logged in, and not that the invoice belongs to them, any customer can read every other customer's records by changing the number. Hiding a link in the interface is not a control.

## How to test
Use two test accounts you own (A and B) and one record that belongs to B. Log in as A and keep A's cookie in a file.
```bash
# 1. A private URL with no cookie at all: expect a redirect to login, 401 or 403
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' https://example.com/account/orders/1042

# 2. B's record requested with A's session: expect 403 or 404, never B's data
curl -s -o /dev/null -w '%{http_code}\n' -b 'session=A_COOKIE_VALUE' https://example.com/account/orders/1042

# 3. Same record through any JSON/API route the front end uses
curl -s -o /dev/null -w '%{http_code}\n' -b 'session=A_COOKIE_VALUE' https://example.com/api/orders/1042
```
Repeat for every verb the object supports (view, edit, delete, download) and for file downloads. In the code, look for queries that fetch a record by its id alone instead of by id plus owner.

## Pass criteria
Requests with no session, and with another user's session, are refused (401, 403 or 404) on every route and verb. Each lookup of a private record is scoped to the current user or role in server code.

## Fix
Make the check part of the data access, for example `WHERE id = ? AND owner_id = ?`, or a central policy function that every route calls. Deny by default for new routes. Do not rely on unguessable ids as the only protection (they are a useful extra, not a substitute).

## Risk and rollback
Adding ownership filters can hide records that staff legitimately view; give staff roles an explicit, logged path. Test with a staging copy and one account per role before release. Rollback: revert the commit; the old behaviour was the exposure, so prefer fixing forward.
