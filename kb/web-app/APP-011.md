# APP-011 · Secrets, backups, repository folders and phpinfo are not reachable over the web, and directory listing is off

## Why it matters
Files meant for the developer often end up inside the folder the web server publishes: `.env` with database passwords and API keys, a `.git` folder holding the whole source history, a `backup.sql` or site archive, a `phpinfo()` page. Attackers request these names automatically on every site they can find. One hit can mean full database access without any hacking. Directory listing makes such files easy to discover.

## How to test
Request common names on your own site and look at both the status and the content, because some sites answer every path with 200.
```bash
for p in .env .git/HEAD .git/config .svn/entries .DS_Store backup.zip backup.sql db.sql dump.sql \
         site.tar.gz wp-config.php.bak config.php.bak phpinfo.php info.php server-status; do
  curl -s -o /dev/null -w "%{http_code} %{size_download} /$p\n" "https://example.com/$p"
done
# Content checks that avoid false positives from catch-all pages
curl -s https://example.com/.git/HEAD | grep -E '^ref:'
curl -s https://example.com/.env | grep -E '^[A-Z][A-Z0-9_]+='
# Directory listing on upload and asset folders
curl -s https://example.com/uploads/ | grep -i 'index of'
```
Do not download or keep any real secret you find; note the path and fix it.

## Pass criteria
Every path above returns 403 or 404 (or a normal site page with none of the content markers). No folder returns an auto-generated index. The web root contains only files meant to be public.

## Fix
Best: publish only a dedicated `public/` folder and keep config, `.git`, dumps and archives elsewhere; delete stray backups and `phpinfo` pages. As a safety net, nginx: `location ~ /\.(?!well-known) { deny all; }` and `autoindex off;` (off by default). Apache: `Options -Indexes` and `RedirectMatch 404 /\.git` (plus a `FilesMatch` deny for `.env`, `.bak`, `.sql`). If a secret was ever exposed, treat it as leaked and rotate it.

## Risk and rollback
Deny rules for extensions such as `.zip` or `.sql` can break legitimate downloads, and blocking all dotfiles must leave `/.well-known/` working for certificate issuance and security.txt. Check the site and certificate renewal after the change. Rollback: remove the one rule and reload, but rotate secrets regardless of rollback.
