# APP-010 · Debug mode is off and error pages do not reveal stack traces or file paths

## Why it matters
Debug pages are written for developers. In production they hand a visitor source paths, library versions, SQL text and sometimes configuration values or secrets, which saves an attacker most of the reconnaissance work. In some frameworks an enabled debug console can even allow code to run. Security misconfiguration is category A05 of the OWASP Top 10:2021.

## How to test
Trigger ordinary, harmless errors and read what comes back.
```bash
# A path that does not exist
curl -si https://example.com/no-such-page-9f3a1c | head -40
# A value of the wrong type where a number is expected
curl -si 'https://example.com/product?id=abc' | head -40
# A malformed JSON body to an API route
curl -si -X POST -H 'Content-Type: application/json' -d '{bad' https://example.com/api/orders | head -40
# Look for typical leak markers in any of the above
curl -s 'https://example.com/product?id=abc' | grep -iE 'traceback|stack trace|fatal error|warning:|notice:|on line [0-9]+|/var/www|/home/|sqlstate|DEBUG = True|whoops'
```
Also check the configuration directly: PHP `display_errors`, Django `DEBUG`, Laravel `APP_DEBUG`, WordPress `WP_DEBUG_DISPLAY`, and `NODE_ENV` for Node apps.

## Pass criteria
Errors return a short generic page and the correct status (404, 400, 500). No stack trace, file path, SQL, framework debug screen or version banner appears. Full error detail is written to a server-side log instead.

## Fix
PHP: `display_errors = Off` and `log_errors = On` in the FPM/Apache `php.ini`, with an `error_log` path. Django: `DEBUG = False` and a real `ALLOWED_HOSTS`. Laravel: `APP_DEBUG=false`. WordPress: `WP_DEBUG` false or `WP_DEBUG_DISPLAY` false. Express: `NODE_ENV=production` plus your own error handler. Add custom 404 and 500 pages, optionally showing a reference code that matches a log line.

## Risk and rollback
With display off, a broken page becomes a blank page or generic 500, so confirm logging works and someone reads the logs. Django with `DEBUG=False` also stops serving static files itself, so the web server must. Rollback: turn debug on temporarily only on a private staging copy, never on the public site.
