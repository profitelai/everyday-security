# APP-012 · Admin and database-management panels are not open to the whole internet

## Why it matters
An admin login that anyone on the internet can reach is a permanent target for password guessing, credential stuffing and exploits for any bug in the admin code. Tools such as phpMyAdmin or Adminer are worse, since they sit right in front of the database. Restricting who can even reach the panel removes most of that exposure, and strong login rules (see APP-005) stay as the second layer.

## How to test
Find the admin addresses from your own knowledge of the app, then request them from a network that is not on your allow-list, such as a phone hotspot. Only your own site, and no guessing of passwords.
```bash
for p in admin/ administrator/ wp-admin/ wp-login.php phpmyadmin/ pma/ adminer.php manager/html; do
  curl -s -o /dev/null -w "%{http_code} /$p\n" "https://example.com/$p"
done
```
A 200 or a login-form redirect from an untrusted network means the panel is exposed. Also check the origin server when a CDN or proxy is in front: request the server's IP directly with the host header and see whether the restriction still holds (`curl -sk --resolve example.com:443:ORIGIN_IP https://example.com/wp-admin/ -o /dev/null -w '%{http_code}\n'`).

## Pass criteria
From an unapproved network, admin and database-tool paths return 403, 404 or a challenge page from an access gateway, or they live on a separate hostname that is itself restricted. Database tools are not installed on the public site at all unless they need to be. The restriction applies to the origin too, not only to the CDN.

## Fix
Allow only known addresses or a VPN at the web server (nginx `allow 203.0.113.10; deny all;` inside the admin `location`, Apache `Require ip`), or put the panel behind an identity-aware gateway such as Cloudflare Access or a private network like WireGuard or Tailscale. Remove phpMyAdmin and Adminer from public hosts, or bind them to localhost and reach them through an SSH tunnel. Renaming the URL is not a control; use it only as a nuisance reducer.

## Risk and rollback
Dynamic home IPs change, so a bad allow-list can lock you out of your own admin; keep a second route in (SSH or the hosting console) before applying it. Some CMS front-end features call endpoints under the admin path (WordPress `admin-ajax.php`), so test forms and checkout after the change. Rollback: remove the `deny` rule and reload.
