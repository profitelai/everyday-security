# APP-005 · Login is rate-limited, admin accounts use MFA, and password reset is safe

## Why it matters
Identification and authentication failures are category A07 of the OWASP Top 10:2021. Login forms that accept unlimited guesses invite password guessing and credential stuffing (reused passwords from other breaches). Admin accounts are the prize, so a second factor matters most there. NIST SP 800-63B requires verifiers to limit failed attempts per account, and the reset flow is often the weakest door into the account.

## How to test
Use a test account you own, because the repeated failures may lock it.
```bash
# 12 wrong-password attempts; watch for 429, a lockout message, or growing delay
for i in $(seq 1 12); do
  curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' -X POST \
    -d 'username=test-user&password=wrong-'$i https://example.com/login
done
# Reset flow: an unknown address and a known one should look the same to the caller
curl -s -X POST -d 'email=nobody-here@example.com' https://example.com/forgot | head -c 400
```
Manual review: does every admin or staff account have MFA enforced (not optional)? Do reset links arrive by email only, expire, work once, and avoid revealing whether the address exists? Does a successful reset end the other sessions?

## Pass criteria
Repeated failures lead to throttling, temporary lockout or an escalating delay, applied per account and per IP. The reset response is the same for known and unknown addresses. Reset tokens are random, single-use and short-lived. Admin accounts must use MFA. Password rules follow NIST: allow long passphrases, no forced composition or periodic rotation, and check against a list of known-compromised passwords.

## Fix
Add throttling in the application (and at the edge: nginx `limit_req` on `/login`, or the CDN's rate rules). Enable MFA with an authenticator app or passkeys for admin roles, and keep recovery codes safe. Make reset tokens high-entropy, store only their hash, and expire them quickly.

## Risk and rollback
Hard lockouts let an attacker lock real users out on purpose; prefer delays or per-IP-plus-account limits, and keep an out-of-band recovery path for the owner so an MFA mistake does not lock out everyone. Rollback: loosen the threshold, not the whole control.
