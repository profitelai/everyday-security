# APP-008 · File uploads are limited by type and size and cannot be run as code

## Why it matters
An upload form lets strangers put files on your server. If an uploaded script lands in a folder where the web server executes code, the visitor gets control of the site. Even harmless-looking uploads can carry stored XSS (an HTML or SVG file served from your domain), fill the disk, or be used to host someone else's content.

## How to test
Do this only on your own site, with a test account.
```bash
# A probe file that prints a marker only if the server executes it as PHP
printf '<?php echo "upload-probe-" . (6*7); ?>' > probe.php
# Upload it through the normal form (field name and URL vary), then fetch it
curl -s -b 'session=YOUR_TEST_COOKIE' -F 'file=@probe.php' https://example.com/upload
curl -s https://example.com/uploads/probe.php | head -c 200
```
Reading `upload-probe-42` means the file was executed: fail. Seeing the source text, a download prompt, 403/404, or a rejection at upload time is fine. Repeat with an oversize file, a `.html` file, and a plain text file sent under the name `../probe.txt` (`-F 'file=@note.txt;filename=../probe.txt'`), which should be rejected or renamed. Then review the server config for the upload directory.

## Pass criteria
Uploads are checked against an allow-list of extensions and content types, with a size cap. Files are stored under server-generated random names. They are kept outside the web root or in a folder where script execution is turned off, and are served with a fixed safe `Content-Type` plus `X-Content-Type-Options: nosniff`. Only logged-in, authorized users can upload.

## Fix
Allow only the formats the business needs (for example `.jpg`, `.png`, `.pdf`). Rename on save, never trust the client's filename or MIME type, and set limits in the app and web server (nginx `client_max_body_size`). Disable execution for the uploads folder (in nginx, no PHP `location` for it; in Apache, remove handlers there). Re-encode images where practical. Consider object storage on a separate domain.

## Risk and rollback
Tightening the allow-list rejects formats that staff or customers already use, for example `.heic` or `.docx`; ask what people really upload before the change. Rollback: add the one format back to the allow-list; do not re-enable script execution in the folder.
