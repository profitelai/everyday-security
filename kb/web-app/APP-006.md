# APP-006 · Sessions are renewed at login, expire, and are ended at logout

## Why it matters
A session cookie is as good as a password while it is valid. If the session id stays the same after login, a planted or leaked pre-login id becomes an authenticated one (session fixation). If logout only deletes the cookie in the browser, a stolen copy keeps working. Idle and absolute time limits shorten how long any stolen cookie is useful.

## How to test
Use a test account.
```bash
# Cookie value before login (if the site sets no cookie until login, skip the comparison)
curl -s -c before.txt -o /dev/null https://example.com/login
# Log in sending the pre-login cookie, then compare the cookie value afterwards
curl -s -b before.txt -c after.txt -o /dev/null -d 'username=test-user&password=TEST_PASSWORD' https://example.com/login
diff before.txt after.txt
# Log out, then replay the post-login cookie against a private page
curl -s -b after.txt -o /dev/null https://example.com/logout   # use POST if the site requires it
curl -s -b after.txt -o /dev/null -w '%{http_code} %{redirect_url}\n' https://example.com/account
# Cookie flags
curl -sI https://example.com/login | grep -i '^set-cookie'
```
Also check in the application settings what idle and absolute lifetimes are configured.

## Pass criteria
The session id differs after login. The old cookie is rejected after logout (redirect to login, 401 or 403). The session cookie carries `Secure`, `HttpOnly` and `SameSite`. Idle timeout and a maximum lifetime exist and suit the data (shorter for admin areas). Ids are random values from a cryptographically secure generator, not sequential or built from user data.

## Fix
Regenerate the id on login and any privilege change (PHP: `session_regenerate_id(true)`; most frameworks do this in their login call). Destroy the server-side session on logout instead of just clearing the cookie. Set the cookie attributes and server-side expiry in configuration.

## Risk and rollback
Short timeouts can log users out mid-task and frustrate form fills; start with a generous idle time and tighten for admin. Rollback: lengthen the lifetime; keep rotation and server-side invalidation in place.
