# APP-002 · Database queries use parameterized statements, never string-built SQL

## Why it matters
When user input is pasted into a SQL string, the database cannot tell the owner's query from the visitor's text. An attacker can then read, change or delete data, or sign in as someone else. Injection is its own category (A03) in the OWASP Top 10:2021. Parameterized queries keep the query and the values separate, which removes the problem at its root.

## How to test
Review the source, since a black-box probe can miss paths. Search for queries built by concatenation or interpolation.
```bash
# Query calls that mention request data or interpolation on the same line
grep -rnE '(query|execute|exec|prepare)[[:space:]]*\(.*(\$_(GET|POST|REQUEST|COOKIE)|\$\{|f"|\+)' --include='*.php' --include='*.py' --include='*.js' --include='*.ts' . | grep -v node_modules
# SQL keywords inside strings that also hold a variable
grep -rniE '"(select|insert|update|delete) .*(\$[a-z_]+|\{[a-z_]+\}|" *[.+])' --include='*.php' --include='*.py' --include='*.js' --include='*.ts' . | grep -v node_modules
```
Treat every hit as a lead to read, not as proof. As a gentle live check on your own site, add a single apostrophe to a numeric or text parameter (`/product?id=5'`) and look for a database error message or a 500 response. A clean page does not prove safety; an error page shows a problem.

## Pass criteria
Every query that includes request data uses placeholders (`?`, `:name`, `$1`) with bound values, or a framework query builder that does so. Values never appear inside the SQL text. Table and column names that come from users are matched against a fixed allow-list.

## Fix
Rewrite each flagged query with prepared statements (PDO prepared statements in PHP, `cursor.execute(sql, params)` in Python, parameter arrays in Node database drivers). Use a least-privilege database account for the web app so a missed spot has a smaller blast radius. Validate input type and length as a second layer.

## Risk and rollback
Rewriting queries can change behaviour at edges (empty strings, `LIKE` wildcards, `IN` lists). Cover each changed query with a test and deploy in small steps. Rollback: revert the individual change; avoid reverting to concatenation as a workaround.
