# BAK-003 · Backups are encrypted and the key is stored apart from the backups

## Why it matters
A backup holds everything the live system holds, often in a form that is easier to take: one archive file. Whoever gets an unencrypted copy gets all the customer data, credentials and mail. The opposite error is also real: if the only copy of the encryption key sits on the machine that was lost, the encrypted backups cannot be opened.

## How to test
1. For each backup tool, confirm encryption is on. restic repositories are always encrypted; for other tools check the configuration (for example the encryption mode chosen when a borg repository was created, or server-side encryption on the storage bucket).
2. Look at the storage itself: open one stored object or file and confirm it is not readable plain data.
3. Find where the password or key lives. Check the backup job's environment file, for example:
```bash
ls -l /etc/backup/ 2>/dev/null; systemctl cat backup.service | grep -i -E 'password|key|environment'
```
4. Confirm a second copy of the key is stored away from the backups and from the host, such as a password manager and a sealed offline note, and that someone other than one person can reach it.

## Pass criteria
All backup copies, including off-site ones, are encrypted. The key or password has at least one copy outside the backed-up host and outside the backup storage. File permissions on the local secret are restricted to the backup user. A restore using only the off-host key copy has been demonstrated.

## Fix
Turn on repository encryption (restic: choose a long random password at init; borg: pick a repokey or keyfile mode and export the key). Store the password in a password manager, and keep an offline copy of any key file. Rotate by adding a new key and removing the old one (restic `key add` and `key remove`).

## Risk and rollback
Losing every copy of the key makes the backups unrecoverable, so verify the off-host copy before relying on the repository. Encrypting existing data usually means starting a new repository; keep the old one until a restore from the new one is proven.
