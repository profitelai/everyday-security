# TLS-006 · Certificate renewal is automatic and monitored

## Why it matters
Most certificate outages come from a renewal job that silently stopped, not from a hard attack. Automation using ACME removes the human step; monitoring catches the day automation breaks.

## How to test
```bash
systemctl list-timers | grep -iE 'certbot|acme'
certbot certificates 2>/dev/null
crontab -l 2>/dev/null | grep -iE 'certbot|acme'
certbot renew --dry-run
```
Use the equivalent for the ACME client in use (acme.sh, Caddy, Traefik, lego).

## Pass criteria
A scheduled renewal exists, a dry run succeeds, and an external check alerts when any certificate has fewer than 14 days left.

## Fix
Enable the ACME client's timer or cron job, and add an expiry check from outside the server (a monitor that connects over TLS and reads the notAfter date).

## Risk and rollback
Renewal hooks that reload the web server must be tested; a failing hook leaves a renewed certificate unused. Keep the old certificate path in place until a reload is confirmed.
