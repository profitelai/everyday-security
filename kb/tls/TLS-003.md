# TLS-003 · Cipher suites are modern and give forward secrecy

## Why it matters
Forward secrecy means that recorded traffic cannot be decrypted later if the server's private key leaks. Suites with RC4, 3DES, export-grade keys, NULL encryption or static RSA key exchange do not meet current guidance.

## How to test
```bash
nmap --script ssl-enum-ciphers -p 443 example.com
```
Look for any suite rated below grade A, any suite using RC4, 3DES, NULL, EXPORT or anonymous (`anon`) key exchange, and any TLS 1.2 suite that does not begin with ECDHE or DHE.

## Pass criteria
Every offered TLS 1.2 suite uses ECDHE (or DHE with at least 2048-bit parameters) and an AEAD cipher (AES-GCM or ChaCha20-Poly1305). TLS 1.3 suites are used as offered by the library.

## Fix
Prefer a maintained generator for the server and OpenSSL version in use rather than hand-written lists, and re-generate when the server software is upgraded. Keep the list short; do not re-enable legacy suites to please one old client.

## Risk and rollback
Removing suites can lock out old clients. Test with the oldest client you must support. Rollback: restore the previous cipher directive.
