# TLS-002 · Certificate is valid, complete, matches the name, and is not close to expiry

## Why it matters
An expired, mismatched or incomplete certificate chain makes browsers show a full-page warning and makes API clients refuse to connect. A missing intermediate certificate works in some browsers and fails in others, which makes it hard to notice.

## How to test
```bash
echo | openssl s_client -connect example.com:443 -servername example.com -showcerts 2>/dev/null | openssl x509 -noout -subject -issuer -dates
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | openssl x509 -noout -checkend 2592000 && echo 'valid for 30+ days'
echo | openssl s_client -connect example.com:443 -servername example.com -verify_hostname example.com 2>&1 | grep -E 'Verify return code|Verification'
```

## Pass criteria
Verify return code is 0 (ok). The name is listed in the certificate's Subject Alternative Names. At least 30 days remain (raise to critical at 7 days). The server sends the leaf and its intermediate(s).

## Fix
Install the full-chain file from the CA (leaf plus intermediates) rather than the leaf alone. Add every public hostname, including `www`, to the certificate. Fix renewal first (see TLS-006) so the problem does not return.

## Risk and rollback
Replacing a certificate needs a service reload but no downtime on nginx/Apache. Keep the previous certificate files until the new one is verified.
