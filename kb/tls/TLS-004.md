# TLS-004 · Plain HTTP redirects to HTTPS, with no mixed content

## Why it matters
If port 80 serves content, or redirects through an unencrypted hop to a different host, a network attacker can intercept the first request. Mixed content (an HTTPS page loading scripts or images over HTTP) lets an attacker alter the page.

## How to test
```bash
curl -sI http://example.com/ | head -n 5
curl -sIL http://example.com/some/path | grep -iE '^(HTTP|location)'
curl -s https://example.com/ | grep -oE '(src|href)="http://[^"]+' | head
```

## Pass criteria
Port 80 answers with a single permanent redirect (301 or 308) to the HTTPS version of the same host and path. The page source contains no `http://` sub-resources.

## Fix
Add a port-80 server block that returns `301 https://$host$request_uri`. Change hard-coded `http://` URLs in templates and the database to `https://` or protocol-relative paths. Then add HSTS (HDR-001).

## Risk and rollback
Do not redirect to HTTPS before the certificate is valid on every hostname. Rollback: remove the redirect block.
