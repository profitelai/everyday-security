# TLS-001 · Only TLS 1.2 and TLS 1.3 are accepted

## Why it matters
TLS 1.0 and 1.1 were formally deprecated in 2021 because their handshake and cipher designs can no longer be made safe. A server that still accepts them lets an attacker on the network push a client down to the weak protocol where one is supported.

## How to test
```bash
openssl s_client -connect example.com:443 -servername example.com -tls1_1 </dev/null 2>&1 | grep -E 'Protocol|alert|handshake failure'
openssl s_client -connect example.com:443 -servername example.com -tls1_2 </dev/null 2>&1 | grep Protocol
openssl s_client -connect example.com:443 -servername example.com -tls1_3 </dev/null 2>&1 | grep Protocol
```
Some OpenSSL builds refuse to offer 1.0/1.1 at all; in that case use `nmap --script ssl-enum-ciphers -p 443 example.com`.

## Pass criteria
TLS 1.0 and 1.1 handshakes fail. TLS 1.2 succeeds. TLS 1.3 succeeds (or is simply not offered on very old stacks, which is a medium finding).

## Fix
nginx: `ssl_protocols TLSv1.2 TLSv1.3;`. Apache: `SSLProtocol -all +TLSv1.2 +TLSv1.3`. Reload the service and re-run the test.

## Risk and rollback
Very old clients (Windows XP, Android 4, old embedded devices) stop connecting. Check access logs for the TLS version in use before the change if clients matter. Rollback: restore the previous directive and reload.
