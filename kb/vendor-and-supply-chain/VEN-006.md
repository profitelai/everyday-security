# VEN-006 · Dependency updates arrive as automated pull requests that a person reviews and tests

## Why it matters
Pinned dependencies (VEN-005) stop surprise changes but also stop fixes, so they only work together with a steady update routine. Tools such as Dependabot and Renovate watch your manifests and open one small pull request per update, which turns "update everything someday" into reviewable changes. The review matters as much as the automation: a pull request that auto-merges without tests or a human look can bring a compromised release straight into production. APP-009 covers finding known vulnerabilities; this check covers the routine that applies updates safely.

## How to test
1. Look for the bot's configuration in each repository.
```bash
ls .github/dependabot.yml .github/dependabot.yaml renovate.json .github/renovate.json .renovaterc 2>/dev/null
cat .github/dependabot.yml
```
   Confirm each ecosystem in use is listed (npm, pip, composer, docker, github-actions) and the schedule is at least weekly.
2. Look at recent history, with the GitHub CLI or the web interface:
```bash
gh pr list --state all --limit 40 --search "author:app/dependabot author:app/renovate"
gh pr list --state open --search "author:app/dependabot author:app/renovate"
```
   Check how many are open and how old the oldest is, and that merged ones were reviewed by a person other than the bot.
3. Check the repository settings: the default branch requires status checks (tests, build) and at least one review before merge; auto-merge, if enabled, is limited to patch updates of dev-only or low-risk packages and only after tests pass.
4. Open one merged update and read what the reviewer looked at: release notes, whether the maintainer changed, new dependencies added, new install scripts (see VEN-007).

## Pass criteria
A bot is configured for every ecosystem that ships to production. Security updates are applied within the window the owner has set (for example critical within days, others within a month). No pull request stays open longer than a few weeks without a written reason. Merges require passing tests and a human review, and major-version bumps are never merged automatically. The same routine covers container base images and CI actions.

## Fix
Add a minimal `.github/dependabot.yml` (or a Renovate preset) with one entry per ecosystem and a weekly schedule, and group low-risk minor and patch updates to reduce noise. Turn on branch protection with required checks. Add a recurring 30-minute slot to review the queue. Where no repository host features exist, run `npm outdated`, `composer outdated`, or `pip list --outdated` on a calendar and treat the output as the queue.

## Risk and rollback
Updates can break the application, and a burst of pull requests can tire the team into rubber-stamping them; grouping and weekly cadence help. Never grant the bot more repository permission than it needs. Rollback: revert the merge commit, redeploy the previous build, and add the package to an ignore list with a dated reason and a reminder to revisit.
