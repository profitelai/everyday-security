# SRV-003 · Only needed services listen, and databases and caches listen on localhost

## Why it matters
Every listening service is attack surface, and forgotten ones are the usual way in: a database with a weak or empty password, a cache with no authentication, an admin panel on a high port, a Node development server left running. A database that only the local web application needs should not be reachable from anywhere else, whatever the firewall says today.

## How to test
```bash
sudo ss -tulpn
# listeners that are NOT loopback-only:
sudo ss -tlnp | awk 'NR==1 || $4 !~ /^(127\.|\[::1\])/'
systemctl list-unit-files --type=service --state=enabled --no-pager
```
`ss` flags: `-t` TCP, `-u` UDP, `-l` listening, `-n` numeric, `-p` owning process. In the Local Address column, `0.0.0.0`, `[::]` or `*` means every interface; `127.0.0.1` or `[::1]` means this machine only. Pay particular attention to ports 3306, 5432, 6379, 11211, 27017 and 9200, and to any application port such as 3000 or 8080.

## Pass criteria
Every non-loopback listener maps to a purpose you can state (web, SSH, SMTP/IMAP on a mail host). Databases and caches use a Unix socket, loopback, or a private interface that is firewalled. Application servers that sit behind nginx or Apache listen on loopback. Enabled services you do not use are disabled. Authentication is on even for local-only services.

## Fix
Bind to loopback in each service's own settings: PostgreSQL `listen_addresses` (its documented default is `localhost`), Redis `bind 127.0.0.1` and keep protected mode on, MariaDB/MySQL `bind-address = 127.0.0.1`, memcached `-l 127.0.0.1`, Node `app.listen(port, '127.0.0.1')`. Restart the service, then repeat the `ss` check. Remove what you do not need with `sudo systemctl disable --now SERVICE`, and uninstall the package if it has no purpose.

## Risk and rollback
Remote tools may stop working: off-server backups, replication, BI dashboards, monitoring agents and developers' database clients. Use an SSH tunnel for occasional admin access rather than reopening the port. Services that talked to a database through its public address need the local address instead. Rollback is restoring the previous bind line and restarting the service; note it is the restart that can briefly interrupt the site, so schedule it in a quiet period.
