# SRV-006 · Repeated failed logins are blocked automatically without locking out the administrator

## Why it matters
Password guessing against SSH, mail (IMAP/SMTP submission) and web logins is continuous and automated. Blocking an address after a handful of failures cuts the volume of guesses sharply and keeps logs readable. It is a compensating control where password login is kept (SRV-001), not a substitute for strong credentials.

## How to test
```bash
systemctl is-active fail2ban
sudo fail2ban-client status
sudo fail2ban-client status sshd
sudo fail2ban-client get sshd ignoreip
sudo fail2ban-client get sshd maxretry; sudo fail2ban-client get sshd bantime
```
The first status command lists the active jails. Look for an `sshd` jail, and for jails covering the other login surfaces you run (for example Postfix, Dovecot, nginx basic auth). Check which addresses are on the ignore list.

## Pass criteria
fail2ban (or an equivalent such as CrowdSec) is running, with jails for SSH and each other exposed login service. `maxretry`, `findtime` and `bantime` are sensible (for example 5 failures in 10 minutes, ban for an hour or more). The administrator's fixed addresses or VPN range are in `ignoreip`. For anything behind a proxy or CDN, the log records the real visitor address, not the proxy's, otherwise a ban would block the proxy and with it every visitor.

## Fix
Install fail2ban and put settings in `/etc/fail2ban/jail.local`, never in the packaged `jail.conf`. Example: under `[DEFAULT]` set `ignoreip = 127.0.0.1/8 ::1 ADMIN_IP`, `findtime = 10m`, `maxretry = 5`, `bantime = 1h`; under `[sshd]` set `enabled = true`. Ready-made filters exist for services such as `postfix`, `dovecot` and `nginx-http-auth`. Reload with `sudo fail2ban-client reload`.

## Risk and rollback
The danger is banning yourself: a mistyped password, a changing home address or a shared office address can block the person who needs access. Always list your own address in `ignoreip` (the `ignoreself` default only covers the server's own addresses), keep a second session or console access, and test with a throwaway address, never with your own. On a banned address run `sudo fail2ban-client set sshd unbanip ADDRESS`. Never apply a blanket ban to a proxy's address range. Rollback: remove the jail section and reload, or `sudo systemctl stop fail2ban`.
