# SRV-002 · The host firewall denies inbound traffic by default and opens only needed ports

## Why it matters
A default-deny firewall means a service started by mistake, or by a package update, is not automatically reachable from the internet. It is a second layer behind careful service configuration (SRV-003), and it limits what an attacker can reach after a partial compromise elsewhere on the network.

## How to test
```bash
sudo ufw status verbose            # where ufw is used
sudo nft list ruleset | head -100  # nftables view (or: sudo iptables -S)
```
Then, from a different computer and against your own server only, list what is truly reachable from outside:
```bash
nmap -Pn -p- --open SERVER_IP
```
Compare the result with what you expect to be public. If a provider-level (cloud) firewall exists, review it too, because it filters before the host does. Remember Docker-published ports can bypass ufw rules (SRV-004).

## Pass criteria
Incoming policy is deny (drop or reject), outgoing is allowed or deliberately restricted. Open ports match the services you run: typically 80 and 443 for a web server, SSH on its chosen port (ideally limited to administrator addresses or a VPN), and on a mail server only the mail ports in use (25, 465, 587, 993, 143, 995, 110 as applicable). Every open port has a named owner and reason. IPv6 is handled as deliberately as IPv4. The external scan shows nothing extra.

## Fix
With ufw, in this order: `sudo ufw default deny incoming`, `sudo ufw default allow outgoing`, `sudo ufw allow 80/tcp`, `sudo ufw allow 443/tcp`, then the SSH rule, for example `sudo ufw allow proto tcp from ADMIN_IP to any port 22`, and only then `sudo ufw enable`. Preview any command with `sudo ufw --dry-run ...`. Use one firewall tool at a time; mixing ufw, firewalld and hand-written nftables or iptables rules produces rule sets nobody can reason about.

## Risk and rollback
Enabling the firewall before the SSH allow rule, or allowing the wrong source address, locks you out. Keep a second SSH session open and test a fresh login before closing anything. Schedule an automatic revert first: `sudo systemd-run --on-active=10m --unit=fw-revert /usr/sbin/ufw disable`, then `sudo systemctl stop fw-revert.timer` once everything works. Never write a deny rule that covers the administrator's own address. On a mail host, closing inbound 25 silently stops incoming mail; send and receive a test message after any change. Rollback: `sudo ufw disable`, or `sudo ufw delete` the specific rule.
