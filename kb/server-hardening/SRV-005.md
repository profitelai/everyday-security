# SRV-005 · Security updates install automatically and pending reboots are handled

## Why it matters
Most compromises of small servers use vulnerabilities that already have a fix. A server that waits for a human to run `apt upgrade` is only as current as the owner's calendar. Kernel and core-library fixes also take effect only after a reboot or service restart, so installing them is half the job.

## How to test
```bash
apt-config dump | grep -E 'APT::Periodic::(Update-Package-Lists|Unattended-Upgrade)'
systemctl list-timers 'apt-daily*' --all --no-pager
sudo unattended-upgrade --dry-run --debug 2>&1 | tail -15
sudo tail -n 20 /var/log/unattended-upgrades/unattended-upgrades.log
apt list --upgradable 2>/dev/null | head
ls -l /var/run/reboot-required && cat /var/run/reboot-required.pkgs; uname -r; uptime -p
```
The file `/var/run/reboot-required` exists only when a package asked for a reboot.

## Pass criteria
Both periodic values are `"1"`, the apt-daily timers are active, and the log shows recent successful runs that included security updates. There is a stated reboot policy: either automatic at a quiet hour (`Unattended-Upgrade::Automatic-Reboot "true"` with `Automatic-Reboot-Time "04:00"`), or manual with an alert or reminder when the reboot-required file appears, and nothing waits longer than the window the owner chose. Software installed outside apt (container images, npm or Composer dependencies, CMS plugins) has its own update routine; see SRV-011.

## Fix
`sudo apt install unattended-upgrades`, then `sudo dpkg-reconfigure -plow unattended-upgrades` to turn on the daily run. Keep your settings in a local override file under `/etc/apt/apt.conf.d/` as the Debian wiki suggests, rather than editing the packaged file. Set `Unattended-Upgrade::Mail` to a mailbox someone reads (it needs a working local mail transport). On Ubuntu, needrestart restarts affected services after updates; read the Ubuntu server documentation to see which services it will and will not restart on your release.

## Risk and rollback
An update can restart a service or, with automatic reboot, restart the machine at the chosen hour; a single-server website and mail host is briefly down. Choose a quiet time and make sure services start on boot (`systemctl is-enabled`). An occasional bad update can break an application; keep backups and the previous package version available. Rollback: set `APT::Periodic::Unattended-Upgrade "0";` to stop automation, and reinstall a specific earlier version with `apt install PACKAGE=VERSION` if one update misbehaves.
