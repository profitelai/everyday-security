# HDR-008 · Responses with private data are not cached by browsers or shared caches

## Why it matters
If an account page, invoice or API response can be stored by a shared proxy or by the browser's back-forward cache on a shared computer, the next person may see it.

## How to test
```bash
curl -sI -H 'Cookie: session=TEST' https://example.com/account | grep -iE 'cache-control|pragma|expires|vary'
```

## Pass criteria
Pages that show private or account data send `Cache-Control: no-store` (or at least `private, no-cache`). Static, public assets may be cached long-term with a fingerprinted file name.

## Fix
Set `Cache-Control: no-store` on authenticated routes in the application or at the proxy. Keep long `max-age` only for versioned static files.

## Risk and rollback
`no-store` removes caching for those pages, which costs some speed. Apply it only where the data is private.
