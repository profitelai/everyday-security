# HDR-007 · Session and authentication cookies carry Secure, HttpOnly and SameSite

## Why it matters
`Secure` keeps the cookie off plain HTTP, `HttpOnly` hides it from page scripts so XSS cannot read it, and `SameSite` limits cross-site sending, which reduces cross-site request forgery.

## How to test
```bash
curl -sI https://example.com/login | grep -i set-cookie
```
Repeat for every cookie the application sets after sign-in.

## Pass criteria
Every session or token cookie has `Secure`, `HttpOnly`, and `SameSite=Lax` (or `Strict`; `None` only with `Secure` and a documented reason). Using the `__Host-` name prefix is a bonus.

## Fix
Set the flags in the framework's session configuration rather than in the web server. For PHP: `session.cookie_secure=1`, `session.cookie_httponly=1`, `session.cookie_samesite=Lax`.

## Risk and rollback
`SameSite=Strict` can log users out when they arrive from an external link; `Lax` is the usual balance. Existing sessions end when the cookie name changes.
