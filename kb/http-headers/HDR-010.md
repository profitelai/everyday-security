# HDR-010 · CORS allows only named origins and never combines a wildcard with credentials

## Why it matters
A permissive cross-origin policy lets any website read responses from your API as the signed-in visitor. Reflecting the request's `Origin` header back without checking it is equivalent to allowing every site.

## How to test
```bash
curl -sI -H 'Origin: https://evil.example' https://example.com/api/me | grep -i access-control
curl -sI -H 'Origin: null' https://example.com/api/me | grep -i access-control
```

## Pass criteria
For an untrusted origin there is no `Access-Control-Allow-Origin` header (or it names only approved sites). `Access-Control-Allow-Credentials: true` never appears with `*`, and an arbitrary or `null` origin is never reflected.

## Fix
Maintain an explicit allow-list of origins in the application, compare the incoming `Origin` exactly, and send `Vary: Origin`. Use `*` only for fully public, credential-free resources.

## Risk and rollback
A too-strict list breaks legitimate front-ends or partner integrations. Collect the real origins from logs before enforcing.
