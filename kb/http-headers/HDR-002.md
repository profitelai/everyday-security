# HDR-002 · A Content-Security-Policy limits where scripts and other resources load from

## Why it matters
CSP is the strongest browser-side defence against cross-site scripting: even if an attacker injects markup, the browser refuses to run scripts the policy does not allow.

## How to test
```bash
curl -sI https://example.com/ | grep -i content-security-policy
```
Then read the policy for `script-src` containing `'unsafe-inline'`, `'unsafe-eval'`, bare `*`, or `data:`.

## Pass criteria
A policy is present. `script-src` uses nonces or hashes (not `'unsafe-inline'`), `object-src 'none'`, `base-uri 'self'`, and `frame-ancestors` is set.

## Fix
Deploy first as `Content-Security-Policy-Report-Only` with a report endpoint, fix what the reports show, then enforce. Example starting point: `default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'self'`.

## Risk and rollback
An enforced policy that is too tight breaks pages (third-party widgets, analytics, inline handlers). Report-only mode first is the rollback-free path.
