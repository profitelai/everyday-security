# CTR-011 · The Docker engine and Compose are kept patched and the host runs a supported version

## Why it matters
Every container shares the host's kernel and relies on the Docker engine (and its runtime components) to keep them apart. Flaws in these components can allow a process in a container to escape to the host, so patching the engine matters as much as patching the images. Because the engine usually comes from a separate package repository, ordinary host updates (SRV-005) may not cover it unless that repository is enabled for automatic updates. An old engine is also one the vendor no longer fixes.

## How to test
```bash
docker version --format 'client={{.Client.Version}} server={{.Server.Version}}'
docker compose version
apt-cache policy docker-ce containerd.io docker-compose-plugin     # Debian/Ubuntu; use your package manager
docker info --format 'live-restore={{.LiveRestoreEnabled}}'
uname -r
```
Compare the installed engine version with the current release on Docker's release-notes page, and look at the security fixes noted since your version. Check whether the Docker repository is covered by the unattended-upgrades configuration, and when the last engine upgrade happened.

## Pass criteria
The engine, containerd and the Compose plugin are installed from the vendor's or distribution's maintained repository, are on a currently supported release, and have received security updates within a stated window (for example, a critical engine fix applied within a week). The owner of the host knows how updates reach it and who watches release announcements. Live-restore is enabled or a maintenance window is agreed for engine restarts. The host kernel is current and reboots are handled (SRV-005).

## Fix
Install Docker from the maintained repository, include it in the host's patch routine, and subscribe someone to the project's release and security announcements. Enable `"live-restore": true` in `daemon.json` so that containers keep running during a daemon upgrade or restart. Upgrade in a quiet period after a backup (CTR-009) and check each service's health afterwards (CTR-010). Remove old packages from distribution repositories that conflict with the vendor ones.

## Risk and rollback
An engine upgrade restarts the daemon, and without live-restore it stops all containers briefly. A new engine version can change defaults, so read the release notes first. Live-restore does not cover every upgrade type (check the documentation for major-version changes). Rollback: reinstall the previous package version pinned in the package manager, then confirm containers start.
