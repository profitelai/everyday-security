# CTR-010 · Containers have healthchecks and their logs are bounded, collected and watched

## Why it matters
A container whose main process is running can still be broken: the web server answers every request with an error, or the database is stuck. Without a healthcheck, Docker reports it as up and nothing is alerted. Logs matter for the opposite reason: the default `json-file` driver keeps container logs without a size limit, so a chatty service can fill the disk and take down the whole host, while at the same time the logs vanish whenever a container is recreated. Bounded, collected logs support both operations and incident investigation. Host log rotation is covered in SRV-010.

## How to test
```bash
docker ps --format 'table {{.Names}}\t{{.Status}}'          # look for "(healthy)" or "(unhealthy)"
docker ps -q | xargs docker inspect --format '{{.Name}} health={{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}} log={{.HostConfig.LogConfig.Type}} {{.HostConfig.LogConfig.Config}}'
docker info --format '{{.LoggingDriver}}'
cat /etc/docker/daemon.json
```
`health=none` means no healthcheck is defined. An empty log config with the `json-file` driver means no size limit unless the daemon sets one.

## Pass criteria
Each service that serves requests or stores data defines a healthcheck that tests real function (an HTTP request to a status path, or the database client's ping), not just that a process exists. Log size is limited either globally in `daemon.json` or per service (`max-size`, `max-file`), or logs go to a driver that does its own rotation. Application logs are shipped or at least kept long enough to investigate an incident (SRV-010 retention rules apply), and unhealthy or restarting containers raise an alert (SRV-012).

## Fix
Add a `healthcheck:` block in Compose (`test`, `interval`, `timeout`, `retries`, `start_period`) and use `depends_on` with `condition: service_healthy` for start-up order. Set rotation in `/etc/docker/daemon.json`, for example `"log-driver": "json-file", "log-opts": {"max-size": "10m", "max-file": "5"}`, or per service under `logging:`. Rotation settings in `daemon.json` apply only to containers created afterwards, so recreate them.

## Risk and rollback
A daemon setting needs a daemon restart, which stops containers unless live-restore is enabled; do it in a quiet period. A badly written healthcheck can mark a healthy service unhealthy; tools that restart on unhealthy would then loop. Roll out with alerting only first. Rollback: remove the block or restore the previous `daemon.json`, then restart.
